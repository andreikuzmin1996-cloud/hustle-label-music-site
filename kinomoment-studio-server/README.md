# КИНОМОМЕНТ STUDIO 2.0

Однопользовательская веб-студия для превращения длинных разрешённых видеоматериалов в YouTube Shorts.

## Возможности
- Импорт YouTube-ссылки (yt-dlp; возможны ограничения YouTube), либо прямой загрузки MP4/MOV/MKV.
- Чанковая расшифровка аудио Groq Whisper; ИИ подбирает сцены в разных 20-минутных частях видео.
- Заголовок, описание и хештеги; субтитры, текст поверх видео, вертикальный рендер FFmpeg.
- Одновременная обработка только одного задания, загрузка ZIP / MP4, удаление временных результатов через 6 часов.
- Пароль студии в `STUDIO_PASSWORD`. Groq ключ только на сервере, не в браузере.

## Публикация на Render
1. Render → New → Blueprint, подключить GitHub `andreikuzmin1996-cloud/hustle-label-music-site`, выбрать `render.yaml` из корня (или создать Web Service Docker с Dockerfile `kinomoment-studio-server/Dockerfile` и Docker Context `kinomoment-studio-server`).
2. В секретных переменных установить `STUDIO_PASSWORD` — длинный уникальный пароль, `GROQ_API_KEY` — секретный ключ с console.groq.com.
3. Развернуть сервис. Использовать сгенерированный Render URL. При желании привязать `studio.hustlelabel.ru` и добавить CNAME по данным Render.
4. Открыть адрес, ввести пароль, подтвердить права на видео, загрузить файл или ссылку и дождаться результата.

Важно: GitHub Pages не запускает Python/FFmpeg. Render Starter на 512 МБ памяти может оказаться недостаточен для длинных фильмов; рекомендуется ≥2 ГБ RAM и достаточно свободного временного диска. Долгая задача на 2 часа может требовать более мощного сервера.

YouTube может ограничить автоматическое получение по ссылке. Не использовать сервис для скачивания контента без разрешения. Отдельные правообладатели могут блокировать опубликованные Shorts. Транскрибация и ИИ потребуют платного или лимитированного API-плана Groq.

Файлы на сервере временные (эпhemeral storage). Они могут пропасть при перезапуске. Данные в памяти задач не переживают рестарт; одновременная работа рассчитана на один процесс приложения.

## Тест без реального YouTube
Запустить Docker сервис и выполнить /health. Затем загрузить разрешённое тестовое видео через UI, получить файлы и проверить субтитры вручную.
